# OpenWrt ubus для Home Assistant

[![hassfest](https://github.com/PastorShlag/homeassistant-openwrt-ubus/actions/workflows/hassfest.yml/badge.svg)](https://github.com/PastorShlag/homeassistant-openwrt-ubus/actions/workflows/hassfest.yml)
[![HACS validate](https://github.com/PastorShlag/homeassistant-openwrt-ubus/actions/workflows/validate.yml/badge.svg)](https://github.com/PastorShlag/homeassistant-openwrt-ubus/actions/workflows/validate.yml)

Интеграция Home Assistant для роутеров и точек доступа на OpenWrt. Она общается с роутером напрямую через `ubus` (JSON-RPC поверх `uhttpd`), ничего не устанавливая на сам роутер: отслеживание устройств, мониторинг системы, Wi-Fi, 4G/5G-модема и MWAN3, управление службами и UCI-конфигурацией.

![Обзор](imgs/overview.png)

> **О форке.** Это самостоятельная ветка проекта [FUjr/homeassistant-openwrt-ubus](https://github.com/FUjr/homeassistant-openwrt-ubus). Синхронизации с оригиналом нет, все изменения живут только в этом репозитории. Проверено на **Home Assistant 2026.11** и **OpenWrt 25.12**.

## Что изменено в форке

Версия **0.0.13**. Относительно оригинала (0.0.10):

**Совместимость с Home Assistant 2026.x**
- Связь «роутер → AP → клиент» переведена с устаревшего `via_device` на `via_device_id`; устройство роутера создаётся до загрузки платформ.
- Поиск устройств в реестре переписан на `async_get_device_by_identifier` и `async_entries_for_config_entry`.
- Данные записи хранятся в `entry.runtime_data` вместо глобального `hass.data`.
- Координаторы получают `config_entry`, слушатели корректно отписываются при выгрузке.
- Устранено предупреждение «Setup of sensor platform is taking over 10 seconds»: модули сенсоров запускаются параллельно, на роутер открывается одна сессия вместо семи.

**Надёжность**
- Если роутер недоступен, сущности становятся `unavailable`, а не показывают старые значения. После возвращения роутера всё восстанавливается без перезапуска HA.
- После перезагрузки роутера клиент перелогинивается автоматически (раньше все запросы отвечали `Access denied` до истечения сессии).
- Неверный пароль определяется отдельно: HA показывает «Требуется повторная авторизация» с формой для нового логина и пароля.
- Сессии `rpcd` корректно закрываются, нет утечек соединений.
- Несколько роутеров в одной установке не мешают друг другу (раньше флаги `mwan3`/`modem_ctrl` были общими, а выгрузка одной записи останавливала координаторы всех остальных).

**Настройки и обслуживание**
- Настройки хранятся в `options` записи (подключение остаётся в `data`); после изменения в форме «Настроить» запись перезагружается сама. Существующие записи переносятся автоматически при первом запуске.
- Устройства-клиенты, которых давно не было на роутере, удаляются автоматически (см. [Очистка устаревших устройств](#очистка-устаревших-устройств)).
- Кнопки запускаются параллельно, как и сенсоры.
- Добавлен русский перевод интерфейса.

**Безопасность**
- Пароль больше не попадает в debug-логи.
- Сервисы `uci_*` доступны только администраторам HA (раньше их мог вызвать любой пользователь).

**Исправленные ошибки**
- Сервис `uci_get` никогда не возвращал значение: разбирал не ту структуру ответа.
- Отключение AP- или MWAN3-сенсоров удаляло устройство Ethernet.
- Белый список Wi-Fi-трекера по IP-префиксу не срабатывал.
- При неожиданном ответе iwinfo все клиенты считались ушедшими; теперь сохраняются последние корректные данные.
- Удалён неработающий сервис `scan_devices`, мёртвый код и дубли (`hostapd`/`iwinfo` используют общую реализацию).

## Возможности

| Область | Что даёт |
|---|---|
| **Трекеры устройств** | Wi-Fi-клиенты (через `iwinfo` или `hostapd`) и проводные клиенты, два режима отслеживания, `consider_home` |
| **Система** | Аптайм, нагрузка (1/5/15 мин), память, температуры, число DHCP-клиентов, conntrack, раздел `/` |
| **Точки доступа** | Сеть, канал, шифрование, число клиентов, режим AP/клиент |
| **Клиенты Wi-Fi** | Сигнал, скорости TX/RX, время подключения, к какой точке подключён |
| **Ethernet** | Состояние и скорость портов, статистика интерфейсов |
| **MWAN3** | Интерфейсы (статус, трекинг, аптайм) и политики (распределение трафика) |
| **4G/5G (QModem)** | Уровень сигнала, оператор, технология, температура, трафик |
| **NLBWMon** | Топ хостов по трафику (по желанию) |
| **Службы** | Переключатели и кнопки start/stop/enable/disable/restart для служб procd |
| **Кнопки** | Перезагрузка роутера, отключение клиента Wi-Fi (kick) |
| **Сервисы HA** | Чтение и запись UCI, вызов методов ubus |

## Подготовка роутера

### Пакеты

На роутере должны быть `rpcd` и `uhttpd` с поддержкой ubus.

**OpenWrt 25.12 и новее** (менеджер пакетов `apk`):

```bash
apk add rpcd uhttpd-mod-ubus
# для кнопки отключения клиентов (если ещё не установлен)
apk add hostapd
```

**OpenWrt 24.10 и старше** (`opkg`):

```bash
opkg update
opkg install rpcd uhttpd-mod-ubus
opkg install hostapd   # по желанию
```

Службы должны работать и стартовать при загрузке:

```bash
service rpcd enable && service rpcd start
service uhttpd enable && service uhttpd start
```

Проверка с машины, на которой стоит Home Assistant:

```bash
curl http://IP_РОУТЕРА/ubus -d '{"jsonrpc":"2.0","method":"call","params":["00000000000000000000000000000000","session","login",{"username":"root","password":"ПАРОЛЬ"}],"id":1}'
```

В ответе должен быть `ubus_rpc_session`. Если вместо него код `6` («Permission denied»), логин или пароль неверны.

### Права доступа (ACL)

Без правил доступа часть данных (имена хостов из DHCP, статистика) может быть недоступна, а имена устройств останутся MAC-адресами.

**Вариант 1. Полный доступ** для пользователя `root`:

```bash
mkdir -p /usr/share/rpcd/acl.d
cat > /usr/share/rpcd/acl.d/root.json << 'EOF'
{
  "root": {
    "description": "Root user full access to ubus",
    "read":  { "ubus": { "*": ["*"] } },
    "write": { "ubus": { "*": ["*"] } }
  }
}
EOF
/etc/init.d/rpcd restart && /etc/init.d/uhttpd restart
```

**Вариант 2. Минимальные права** (рекомендуется, если используется отдельный пользователь: замените `root` в имени файла и внутри JSON):

```bash
cat > /usr/share/rpcd/acl.d/root.json << 'EOF'
{
  "root": {
    "description": "Home Assistant access",
    "read": {
      "ubus": {
        "session": [ "access", "login", "list", "destroy" ],
        "system": [ "board", "info" ],
        "iwinfo": [ "devices", "info", "assoclist" ],
        "hostapd.*": [ "*" ],
        "network.interface": [ "dump" ],
        "network.device": [ "status" ],
        "network.wireless": [ "status" ],
        "dhcp": [ "ipv4leases", "ipv6leases" ],
        "file": [ "read" ],
        "uci": [ "get" ],
        "rc": [ "list", "init" ],
        "mwan3": [ "get" ]
      },
      "file": {
        "/proc/stat": [ "read" ],
        "/etc/ethers": [ "read" ],
        "/tmp/dhcp.leases": [ "read" ],
        "/var/dhcp.leases": [ "read" ]
      }
    },
    "write": {
      "ubus": {
        "hostapd.*": [ "del_client" ],
        "file": [ "exec" ],
        "rc": [ "init" ]
      },
      "file": {
        "/usr/sbin/nlbw": [ "exec" ]
      }
    }
  }
}
EOF
/etc/init.d/rpcd restart && /etc/init.d/uhttpd restart
```

Что нужно дополнительно в зависимости от включённых функций:

| Функция | Что добавить |
|---|---|
| Проводные трекеры | в `write.file`: `"/sbin/ip": [ "exec" ]` (используется `ip neigh`) |
| Топ хостов NLBWMon | в `write.file`: `"/usr/sbin/nlbw": [ "exec" ]` (уже есть в примере выше) |
| Управление службами | `rc.init` (уже есть выше) |
| Кнопка перезагрузки | в `write.ubus`: `"system": [ "reboot" ]` |
| Сервис `uci_set_commit` | в `write.ubus`: `"uci": [ "set", "commit" ]` |
| Сервис `uci_network_interface` | в `write.ubus`: нужный объект и метод, например `"network.interface.wwan": [ "up", "down" ]` |

После изменения ACL всегда перезапускайте `rpcd` и `uhttpd`. Сообщения вида `Access denied` в логе HA почти всегда означают устаревший ACL.

## Установка

### Через HACS (рекомендуется)

1. HACS → три точки → **Custom repositories**.
2. Адрес: `https://github.com/PastorShlag/homeassistant-openwrt-ubus`, тип **Integration** → **Add**.
3. Найдите «OpenWrt ubus» → **Download**.
4. Перезагрузите Home Assistant.

> Если у вас уже установлена версия оригинального проекта через HACS, сначала удалите её запись в HACS: домен `openwrt_ubus` один, две копии работать не могут. Записи конфигурации (ваши роутеры) при этом сохранятся.

### Вручную

```bash
git clone https://github.com/PastorShlag/homeassistant-openwrt-ubus.git
cp -r homeassistant-openwrt-ubus/custom_components/openwrt_ubus /config/custom_components/
```

Перезагрузите Home Assistant.

### Добавление роутера

**Настройки → Устройства и службы → Добавить интеграцию → OpenWrt ubus**. Можно добавить несколько роутеров, каждый как отдельную запись.

## Настройка интеграции

### Подключение

| Параметр | Описание | По умолчанию |
|---|---|---|
| Host | Имя или IP роутера | — |
| IP address | Адрес для подключения, если он отличается от `host` (имя из `host` остаётся для TLS) | пусто |
| Use HTTPS / Port | Использовать HTTPS и порт | выкл. / 80 (443 для HTTPS) |
| Verify SSL | Проверять сертификат | выкл. |
| Endpoint | Путь ubus на `uhttpd` | `ubus` |
| Username / Password | Учётные данные rpcd | — |
| Wireless software | Источник данных о Wi-Fi-клиентах: `iwinfo`, `hostapd`, `none` | `iwinfo` |
| DHCP software | Источник имён хостов: `dnsmasq`, `odhcpd`, `ethers`, `none` | `dnsmasq` |
| Tracking method | Режим трекера: `combined` или `uniqueid` | `combined` |

> При включённом HTTPS без проверки сертификата соединение шифруется, но подлинность роутера не проверяется. Включайте **Verify SSL**, если у роутера доверенный сертификат.

### Повторная авторизация

Если на роутере сменили пароль, HA покажет уведомление «Требуется повторная авторизация». Нажмите на него и введите новые логин и пароль.

## Отслеживание устройств

### Режимы

| | `combined` (по умолчанию) | `uniqueid` |
|---|---|---|
| Сущностей на устройство | по одной на каждую AP | одна на всю сеть |
| Роуминг | создаётся новая сущность на новой AP | обновляются атрибуты |
| Иерархия устройств | устройство подчинено своей AP | без привязки к AP |
| Текущая AP | в имени сущности | атрибуты `router`, `ap_device`, `ap_ssid` |
| Подходит для | раздельных сетей, учёта «где именно» | mesh-сетей, простого «дома/не дома» |

При смене режима идентификаторы существующих сущностей мигрируются автоматически.

> В режиме `uniqueid` одно и то же устройство может попасть в несколько роутеров с общим идентификатором. По новым правилам Home Assistant устройство принадлежит одной записи конфигурации, поэтому для нескольких роутеров лучше использовать `combined`.

### Wi-Fi-трекеры

Включаются параметром **Enable Wireless Device Tracking**. **Whitelist** принимает префиксы IP или MAC через запятую (например, `192.168.1,AA:BB:CC`); пустой список означает «отслеживать всех».

### Проводные трекеры

Включаются параметром **Enable Wired Device Tracking**. Работают по таблице соседей роутера (`ip neigh`) и показывают устройства, подключённые не по Wi-Fi.
- **Name priority**: чем называть устройство, если нет имени хоста (`ipv4`, `ipv6`, `mac`).
- **Whitelist**: префиксы IP/MAC, как выше.
- **Interfaces**: ограничить интерфейсами (например, `br-lan`).

### Очистка устаревших устройств

Каждый клиент, который хоть раз подключился к роутеру, получает в Home Assistant своё устройство и сущности. Чтобы они не копились вечно со статусом «недоступно», интеграция запоминает, когда каждый клиент последний раз был в сети (данные хранятся между перезапусками), и раз в 6 часов удаляет устройства, которых не было дольше заданного срока.

- Параметр **«Удалять устройства, не появлявшиеся (дней)»** в форме «Настроить»; по умолчанию **30**, значение **0** отключает очистку.
- Удаляются только клиентские устройства (с MAC-адресом); роутер, точки доступа, MWAN3 и модем не затрагиваются.
- У клиентов, которые уже есть в системе, отсчёт начинается с момента обновления, поэтому сразу после обновления ничего не удаляется.
- Очистка не запускается, пока интеграция не получила данные от роутера: после долгой недоступности роутера устройства не пропадут.
- Если удалённое устройство снова подключится, оно будет создано заново.

### Consider home

Устройство считается дома ещё `consider_home` секунд после последнего появления в сети (по умолчанию **300**). Это убирает ложные «ушёл» из-за режима энергосбережения телефонов.

## Сущности

### Система

Аптайм, нагрузка (1/5/15 мин), память (всего, свободно, доступно, буферы, кэш), температуры, conntrack, количество DHCP-клиентов, использование корневого раздела.

![Системные сенсоры](imgs/system_info_sensor.png)

### Точки доступа и клиенты

Для каждого AP-интерфейса создаётся устройство с сенсорами сети. Для каждого подключённого клиента (если включены STA-сенсоры) создаются сенсоры сигнала, скоростей и времени подключения; клиент появляется как дочернее устройство той AP, к которой подключён (в режиме `combined`).

![Точка доступа](imgs/ap_info_master.png)
![Клиенты](imgs/sta_info_sensor.png)

Кнопка отключения (**kick**) отправляет `deauth` клиенту через `hostapd` и запрещает повторное подключение на 60 секунд. Требует `Wireless software = hostapd`, пакет `hostapd` с поддержкой ubus и права `del_client` в ACL. По умолчанию отключена.

![Kick](imgs/ap_control_kick_sta.png)

### MWAN3

Для каждого интерфейса и политики создаётся своё устройство.
- **Интерфейс**: статус (online/offline/disabled), трекинг, аптайм, счётчики трекинг-IP (up/down/skipped/total).
- **Политика**: список используемых интерфейсов с долей трафика (IPv4 и IPv6), основной интерфейс, число активных.

### QModem

При наличии пакета с `modem_ctrl`: уровень и качество сигнала (RSSI, SINR), состояние регистрации, оператор, технология (4G/5G), температура, объём трафика.

![QModem](imgs/qmodem_info.png)

### Службы

Включается параметром **Enable Service Controls**; выбирается список служб procd (`dnsmasq`, `dropbear`, `firewall`, `network`, `uhttpd`, `odhcpd`, `rpcd` и др.). Для каждой создаются переключатель и кнопки start/stop/enable/disable/restart.

![Службы](imgs/service_control.png)

## Сервисы (UCI)

Три сервиса для работы с настройками роутера. **Доступны только администраторам Home Assistant.**

Если роутер один, он выбирается автоматически. Если роутеров несколько, укажите `config_entry_id` (в интерфейсе это выбор роутера).

### `openwrt_ubus.uci_get`

Читает значение UCI и, при желании, записывает его в состояние сущности.

| Поле | Обязательно | Описание |
|---|---|---|
| `config` | да | Имя конфигурации (`firewall`, `wireless`, `dhcp`…) |
| `section` | нет | Секция (`block_user_7085c2`, `@rule[3]`) |
| `option` | нет | Параметр (`enabled`) |
| `target_entity_id` | нет | Сущность, в чьё состояние записать результат |
| `config_entry_id` | нет | Роутер (если их несколько) |

```yaml
action: openwrt_ubus.uci_get
data:
  config: firewall
  section: block_user_7085c2
  option: enabled
  target_entity_id: sensor.block_user_7085c2_enabled
```

### `openwrt_ubus.uci_set_commit`

Записывает значение, сохраняет конфигурацию и при необходимости перезапускает службы.

| Поле | Обязательно | Описание |
|---|---|---|
| `config` | да | Имя конфигурации |
| `section` | да | Секция |
| `option` | да | Параметр |
| `value` | да | Новое значение (строка) |
| `service` | нет | Служба или список служб для перезапуска |
| `config_entry_id` | нет | Роутер |

```yaml
action: openwrt_ubus.uci_set_commit
data:
  config: firewall
  section: block_user_7085c2
  option: enabled
  value: "1"
  service: firewall
```

### `openwrt_ubus.uci_network_interface`

Вызывает метод объекта ubus (поля `section` и `option` задают объект и метод), например включение интерфейса:

```yaml
action: openwrt_ubus.uci_network_interface
data:
  section: network.interface.wwan
  option: up
```

### Пример: выключатель интернета для одного устройства

Правило файрвола `block_user_7085c2` блокирует MAC-адрес; параметр `enabled` включает или выключает блокировку.

```yaml
# configuration.yaml
template:
  - switch:
      - name: "Интернет у телефона"
        unique_id: user_7085c2_internet
        # блокировка выключена (0) = интернет разрешён
        state: "{{ is_state('sensor.block_user_7085c2_enabled', '0') }}"
        turn_on:
          - action: openwrt_ubus.uci_set_commit
            data: { config: firewall, section: block_user_7085c2, option: enabled, value: "0", service: firewall }
        turn_off:
          - action: openwrt_ubus.uci_set_commit
            data: { config: firewall, section: block_user_7085c2, option: enabled, value: "1", service: firewall }

# automations.yaml: раз в минуту синхронизировать сенсор с роутером
- alias: "Синхронизация блокировки 7085C2"
  triggers:
    - trigger: time_pattern
      minutes: "/1"
  actions:
    - action: openwrt_ubus.uci_get
      data:
        config: firewall
        section: block_user_7085c2
        option: enabled
        target_entity_id: sensor.block_user_7085c2_enabled
```

## Поведение при сбоях

- **Роутер выключен или недоступен.** Все сущности этого роутера становятся `unavailable` и сами возвращаются, когда роутер снова отвечает. Пока роутер недоступен, опрос делает одну быструю попытку, а не серию повторов.
- **Роутер перезагрузился.** Интеграция автоматически входит заново; перезапуск HA не нужен.
- **Сменился пароль.** HA запускает повторную авторизацию.
- **Нет прав на отдельные вызовы.** Соответствующая группа сенсоров остаётся пустой, остальное работает; в логе будет `Access denied`: дополните ACL.
- **Несколько роутеров.** Каждый работает независимо; выгрузка или ошибка одного не влияет на остальные.

## Диагностика

**Не удаётся подключиться**
- Проверьте адрес и доступность из HA, запущены ли `rpcd` и `uhttpd`: `service rpcd status && service uhttpd status`.
- Проверьте логин через `curl` (см. [Подготовка роутера](#подготовка-роутера)).
- Если используется HTTPS, проверьте порт и, при самоподписанном сертификате, отключите **Verify SSL**.

**Неверный логин/пароль** показывается отдельным сообщением. Если пароль верен, проверьте, что пользователь описан в ACL (`/usr/share/rpcd/acl.d/*.json`).

**Нет устройств в трекере**
- Убедитесь, что трекеры включены (по умолчанию они выключены).
- Проверьте `Wireless software`: `iwinfo` или `hostapd` должны соответствовать роутеру. `ubus list | grep hostapd` покажет, есть ли hostapd.
- Для имён хостов проверьте доступ к `/tmp/dhcp.leases` (или `/var/dhcp.leases`).

**Вместо имён MAC-адреса**: добавьте права на чтение файла аренд и `/etc/ethers` (см. ACL), перезапустите `rpcd`.

**Не работает kick**: нужен `Wireless software = hostapd`, `ubus list | grep hostapd` должен что-то показывать, в ACL должен быть `del_client`.

**Топ хостов NLBWMon пуст**: установите `nlbwmon` и разрешите `file.exec` для `/usr/sbin/nlbw`, либо отключите этот сенсор.

### Журнал отладки

```yaml
# configuration.yaml
logger:
  default: warning
  logs:
    custom_components.openwrt_ubus: debug
```

Пароль в журнале маскируется, но ответы роутера (имена хостов, MAC-адреса) в нём остаются: учитывайте это, когда прикладываете журнал к обращению.

## Разработка

### Структура

```
custom_components/openwrt_ubus/
├── __init__.py              # Запуск записи, проверка возможностей роутера, очистка устройств
├── runtime.py               # Данные записи (entry.runtime_data)
├── services.py              # Сервисы uci_get / uci_set_commit / uci_network_interface
├── device_utils.py          # Помощники для via_device_id
├── stale_devices.py         # Очистка давно не появлявшихся клиентов
├── config_flow.py           # Настройка, options flow, повторная авторизация
├── const.py                 # Константы и значения по умолчанию
├── shared_data_manager.py   # Общий клиент, кэш и координаторы данных
├── extended_ubus.py         # Клиент ubus: batch-вызовы, hostapd, UCI, службы
├── Ubus/
│   ├── const.py             # Константы протокола
│   └── interface.py         # Низкоуровневый JSON-RPC клиент (сессии, повторный вход)
├── device_tracker.py        # Трекеры устройств
├── sensor.py, switch.py, button.py   # Платформы
├── sensors/                 # system, ap, sta, eth, mwan3, qmodem, nlbwmon
├── buttons/                 # service, device_kick, reboot
├── services.yaml, strings.json, manifest.json
└── translations/            # en, ru, zh, it
```

### Архитектура

1. **`ExtendedUbus`**: клиент ubus на `aiohttp` с batch-запросами; один клиент и одна сессия `rpcd` на роутер, повторный вход при потере сессии.
2. **`SharedUbusDataManager`**: единый источник данных для всех платформ, кэш с интервалами по типам данных, учёт доступности роутера.
3. **`SharedDataUpdateCoordinator`**: координаторы по группам сущностей; при недоступности роутера выбрасывают `UpdateFailed`, и сущности становятся `unavailable`.
4. **Платформы**: сущности подписываются на координаторы; отписка при выгрузке записи выполняется через `entry.async_on_unload`.

### Проверка изменений

Перед отправкой изменений: перезагрузить интеграцию из интерфейса, посмотреть журнал на предупреждения об устаревших вызовах, проверить отключение роутера (сущности должны стать `unavailable` и вернуться), смену пароля (должна запуститься повторная авторизация) и работу сервисов `uci_*`. Проверку `hassfest` выполняют workflows репозитория.
